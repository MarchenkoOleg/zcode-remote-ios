# ТЗ: гибридный клиент ZCode Remote

## Цель

Убрать WebKit из основного цикла работы приложения. WKWebView используется **только один раз** для входа в z.ai и получения JWT; после этого вся сессия живёт в нативном `URLSessionWebSocketTask`.

Причины: текущая обёртка держит WebContent-процесс, загружает ~4,6 МБ JS, исполняет DOM/MutationObserver и мост `WKScriptMessage` на каждый WebSocket-кадр. По логам с iPhone за ~18 с проходило ~900 кадров моста.

## Ожидаемый выигрыш (прикидка)

| Метрика | Сейчас | После гибрида |
|---|---|---|
| Память | WebContent + JS на каждую сессию | минус ~60–80% |
| CPU / батарея | JS-движок, DOM, мост сообщений | минус ~30–50% |
| Холодный старт | 1,3–1,5 с загрузки страницы | ~0,8–1,0 с (токен + WS) |
| Задержка ввода | событие → JS → мост → WS | нативный send, минус ~5–15 мс |
| Фон / реконнект | страница замирает «Page is in background» | нативный heartbeat и реконнект |

Сеть (RTT 50–150 мс) остаётся главным ограничением задержки.

## Этапы

### Этап 1 — получение JWT (сейчас в работе)

- Скрытый `WKWebView` с тем же `WKWebsiteDataStore(forIdentifier:)` аккаунта.
- После успешного входа — чтение JWT из хранилища страницы (точные ключи уточняются по JS-бандлу).
- токен не попадает в логи; хранится в Keychain с `WhenUnlockedThisDeviceOnly`.
- Fallback: пользователь вставляет JWT вручную в настройках аккаунта.

**Критерий:** для авторизованного аккаунта `NativeRemoteClient.connect()` получает `token` от `/api/v1/remote/token` без участия веб-страницы в дальнейшем.

### Этап 2 — транспорт (готов)

`Sources/NativeRemote/NativeRemoteClient.swift` + `NativeRemoteProtocol.swift`:

- обмен `auth_init`/`auth_ack`;
- разбор `type: data` и `payload.zcode_type`;
- сборка фрагментов `rpc-frame` и ACK;
- heartbeat `pair_status_query` каждые 5 с;
- тесты на разбор конверта и сборку фрагментов.

**Критерий:** подключение к relay, `pair_status: matched`, пересылает heartbeat без ошибок.

### Этап 3 — прикладной слой (первая очередь)

Реализовать минимальный набор сообщений, необходимый чтобы показать список рабочих пространств:

1. `bootstrap-request` → `bootstrap-response` (`requestId`, `workspaces`, `desktopAppVersion`);
2. `workspace-list-request` → `workspace-list-response`/`updated`;
3. `workspace-bridge-open` → `workspace-bridge-ready`/`error`;
4. `mobile-view-state-update` (активное пространство и задача).

**Критерий:** нативный экран показывает те же пространства, что и веб-клиент; выбор проекта открывает мост.

### Этап 4 — RPC и данные задач

- Декодер собственного бинарного формата VS Code-style RPC из `dataBase64` (теги, varint, JSON-тела).
- Подмножество сервисов: список задач, список сообщений чата, отправка сообщения, статус任务和 permissions.
- Режим replayable: snapshot, `fromSeq/toSeq`, resync при пропуске.

**Критерий:** список задач и чат открываются и обновляются в реальном времени без WKWebView.

### Этап 5 — переход и откат

- Переключатель «WebKit / Native» в настройках с сохранением последнего успешного режима.
- При ошибке протокола — автоматический откат на WKWebView.
- Метрики: время подключения, количество reconnect, память, задержка ввода.

**Критерий:** оба режима работают на одном аккаунте; откат занимает ≤ 1 с.

## Ограничения и риски

- Протокол — внутренний контракт `zai-org/ZCode`, без публичной гарантии совместимости. Обновление ZCode может сломать клиент.
- Сторонние реализации (например, `ZCode-Android`) подтверждают принципиальную возможность, но предупреждают о хрупкости.
- ZCode поддерживает только локали `zh-CN`/`en-US`; нативный интерфейс может быть русским, но UI самого ZCode — нет.
- Полный отказ от WebKit требует реализации ~39 сервисных каналов и всего UI; гибрид даёт основную выгоду при меньшем объёме работ.

## Текущий статус

- Этап 1 готов: `HybridSignInView` читает JWT из `oauth:browser_session` / `zcodejwttoken` / `oauth:zai:access_token` в изолированном `WKWebsiteDataStore` и сохраняет его в Keychain. Ключи подтверждены по JS-бандлу (`index-B-ilXaCQ.js`, строка 935).
- Этап 2 готов: транспорт Relay V2.
- Тесты: 16 тестов в 5 наборах проходят.
- Этап 3 в работе: добавлены `bootstrap-request`, `workspace-list-request`, `workspace-bridge-open`, `mobile-view-state-update` и разбор ответов; поверх них работает первый RPC-вызов (см. этап 4).
- Этап 4 частично сделан: `RPCBinaryCodec` разбирает и сериализует бинарный формат (теги, varint, JSON-объекты), `RPCMessage` разбирает запросы/ответы, `CRC32` считает контрольную сумму кадра. Добавлен вызов `zcodeTaskService.listTasks` как первого сервисного метода. Остальные сервисы и чат ещё не реализованы.
- Этап 5 частично: бета-режим открывается из меню `ⓘ → Нативный режим (бета)`, откат на WebKit — закрытием экрана; автоматического фолбэка пока нет.

Отладочный запуск: `native` сразу открывает нативный экран, `switch-language=<...>` переключает язык без перезапуска.
